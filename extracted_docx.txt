Version 1.0 | Frontend-first | React + TypeScript | Backend planned for a later phase
Visual direction: warm ivory (#F4F1EA), charcoal (#171717), signal orange (#FF4D16), white cards (#FFFFFF), and warm-gray borders (#E2DED5). Use the supplied ChaseHorse logo and the uploaded design reference as the primary brand guidance.
1. Project objective and delivery scope
Build a premium, responsive ChaseHorse website for the Growth Enabler Logiworkx Platform (GELP). The first delivery phase is frontend-only. Use React + TypeScript with Vite and reusable UI components. The Spring Boot backend, Supabase Auth integration, live business data, payments and real booking workflows are planned for a later phase. Frontend prototypes must not claim that these integrations are live.
Primary objective: communicate ChaseHorse's broad capabilities across business services, consulting, growth, technology, field operations, logistics, sustainability and customer experience.
Build the complete public website and service-page hierarchy, not only a single landing page.
Keep all service content, routes, navigation definitions and images in structured, reusable configuration where practical.
Use clearly labelled demo/sample data until approved backend APIs are connected.

3. Global navigation and interaction rules
Desktop navigation should have the logo on the left, spacious menu items, and account actions on the right. Use animated mega-menus similar in interaction quality to the project44 reference specified in the source requirements.
Navigation: Platform, Solutions, Live Market, Discover, HSE Shop, Careers, Partners and Login. Keep Login on the right; Partners should sit next to Login as specified in the source document.
Desktop: hover or keyboard focus opens a large mega-menu below the navbar; pointer movement into the panel must not close it. Use smooth fade/slide/scale motion and a short close delay.
Mobile/touch: use click/tap to open menus; do not rely on hover.
Mega-menu cards should include relevant images or icons, title, concise description and a working route.
No dead links, placeholder '#' links, or controls that look functional but do nothing.
Login should open in a separate tab/window if that remains the agreed business requirement; confirm exact behavior before production.

15. Technical frontend architecture
React + TypeScript + Vite.
React Router for routing.
Tailwind CSS or the existing agreed styling system; avoid adding competing styling frameworks without reason.
Framer Motion for menus, logo intro, card transitions and service-section reveals.
Recharts for charts only where relevant.
Lucide icons for consistent iconography.
React Three Fiber / Three.js only for the India map if justified and performance-tested.
Feature-based folders, shared layout components, typed data models, reusable page templates and a service/API abstraction layer.
Keep all sample data isolated from components and clearly marked as demo-only.

17. Delivery milestones
M1 — Foundation: Inspect repo and assets, set design tokens, typography, routing, project structure and basic build.
M2 — Navigation: Build sticky navbar, logo intro, accessible animated mega-menus and all menu cards/routes.
M3 — Homepage: Build hero, video/image sequence, platform overview, three-tier cards, branch map and footer.
M4 — Service catalogue: Build all tier pages, all individual service pages and optional subservice workflows.
M5 — Remaining pages: Build Live Market, Discover, HSE Shop, Partners, Careers, Login and client dashboard UI.
M6 — DIY selector: Build tier checkbox selector, selected-service summary and price calculation only from approved data.
M7 — Quality review: Responsive, accessibility, route, animation, broken-image, lint, typecheck and production-build verification.
Later backend phase: Spring Boot REST API, Supabase Auth, PostgreSQL migrations, secure JWT validation, real bookings, payments and live data.
